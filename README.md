# Анонимная обратная связь от студентов к преподавателю

Веб-сервис, в котором студенты **анонимно** оценивают занятия и дисциплины, а преподаватели
видят обезличенную статистику и текстовые пожелания. Администратор управляет преподавателями,
дисциплинами и темами и видит все отчёты.

Реализованы **две анкеты**. Формулировки дословно соответствуют анкетам преподавателя
(`docs/anketa-zanyatie.pdf` и `docs/anketa-disciplina.pdf`) и собраны в одном файле —
`server/questions.js`:

1. **«Анкета оценки качества проведенного занятия»** — 4 блока: 12 пунктов по шкале от 1 до 5
   (1 — совершенно не согласен, 5 — полностью согласен) и 2 открытых вопроса.
2. **«Итоговая анкета оценки дисциплины и работы ведущего преподавателя»** — 5 блоков:
   15 пунктов по шкале от 1 до 5 и 3 открытых вопроса.

Сайт студентов и служебные разделы работают на **разных портах**:

| Порт | Переменная в `.env` | Что открывается |
| --- | --- | --- |
| `3000` | `PORT` | сайт студентов: список дисциплин и анкета (без входа) |
| `3001` | `STAFF_PORT` | вход, портал преподавателя, админ-панель |

На студенческом порту `/login`, `/portal/`, `/admin/` и их API не существуют вовсе — отдают 404.
Ссылки и QR-коды для студентов всегда формируются на студенческий адрес.

## Быстрый старт

Требования: **Node.js 22 или новее** (рекомендуется 24 LTS) и npm.
Node.js 22+ нужен, потому что только для него драйвер базы данных `better-sqlite3` 12
поставляется готовым бинарником — компилятор на компьютере не требуется.

> **Windows?** Есть готовый релиз и скрипт запуска в один шаг — см. [Установка на Windows (PowerShell)](#установка-на-windows-powershell--самый-простой-путь).

```bash
# 1. Установить зависимости
npm install

# 2. Создать файл настроек (необязательно на первом запуске, но полезно)
cp .env.example .env
#    В .env стоит задать JWT_SECRET и, при желании, ADMIN_PASSWORD

# 3. Заполнить базу: администратор, преподаватель, дисциплины и темы
#    (--demo дополнительно загружает примеры анонимных ответов)
npm run seed -- --demo

# 4. Запустить сервер (поднимутся два порта: студенческий и служебный)
npm start
```

После запуска доступны адреса:

| Порт | Адрес | Для кого |
| --- | --- | --- |
| `3000` | `/` | студенты: выбор дисциплины и переход к анкете |
| `3000` | `/form.html` | заполнение анкеты (без регистрации) |
| `3001` | `/login` | вход для преподавателей и администратора |
| `3001` | `/portal/` | портал преподавателя |
| `3001` | `/admin/` | админ-панель |

### Учётные записи

Пароли берутся из `.env` (шаблон `.env.example` уже содержит демонстрационные значения):

| Роль | Логин | Пароль | Откуда |
| --- | --- | --- | --- |
| Администратор | `admin` | `Admin#2026pass` | `ADMIN_PASSWORD` в `.env` |
| Преподаватель (демо) | `ivanova` | `Teacher#2026pass` | `DEMO_TEACHER_PASSWORD` в `.env` |

Это значения для просмотра сервиса на своём компьютере — перед реальной работой замените их
в `.env` (до первого запуска, пока база не создана). Если `ADMIN_PASSWORD` оставить пустым,
пароль будет сгенерирован и напечатан в консоли при первом запуске, а система попросит сменить
его после входа:

```
Администратор создан: логин «admin», пароль «rbdbV-9dtN9-gdNCH-ny8BU»
```

> ⚠️ В `.env` значения с символами `#` или `;` обязательно заключайте в кавычки —
> `ADMIN_PASSWORD="Admin#2026pass"`. Иначе dotenv считает `#` началом комментария и пароль
> обрежется до `Admin`.

### Сброс данных

```powershell
npm run reset          # удалить файл базы и создать её заново (администратор + структура)
npm run reset -- --demo   # то же + примеры анонимных ответов
.\start.ps1 -Reset       # то же самое при запуске скриптом (Windows)
```

Ручной вариант: удалить каталог `data` и запустить `npm run seed -- --demo`.

Команды:

```bash
npm start        # запуск сервера
npm run dev      # запуск с автоперезапуском при изменении файлов
npm test         # автотесты (108 проверок: анкеты по PDF, API, роли, XSS, порты,
                 #              rate-limit, фронтенд-контракт и дизайн-токены)
npm run seed     # создать администратора, преподавателя, дисциплины и темы
npm run reset    # ПОЛНЫЙ СБРОС: удалить файл БД и создать заново
npm run qr       # напечатать QR-код со ссылкой на анкету в терминале
npm run doctor   # проверить окружение: Node.js, драйвер БД, порт, состояние базы
npm run dbcheck  # отдельно проверить базу данных (запись, чтение, транзакции)
npm run secaudit # локальная проверка безопасности своего развёртывания (отчёт в терминале)
npm run help     # шпаргалка по всем командам
```

Скрипты запуска «в один клик» (установка + старт сервера): `start.ps1` и `start.cmd` (Windows),
`start.sh` (macOS и Linux).

## Установка на Windows (PowerShell) — самый простой путь

Нужен только **Node.js 22 LTS** ([скачать](https://nodejs.org/ru/download)) — установите со стандартными
настройками и **откройте PowerShell заново**, чтобы команда `node` появилась в PATH.

### Вариант A. Скачать готовый релиз и запустить скриптом

Откройте PowerShell и вставьте блок целиком:

```powershell
# 1) проверить Node.js (нужен 22 или новее; если не установлен — см. следующий блок)
node -v

# 2) скачать архив релиза во временную папку
$ProgressPreference = 'SilentlyContinue'
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
$zip = "$env:TEMP\bogusa-feedback-v1.0.3.zip"
Invoke-WebRequest 'https://github.com/Igorr112323/Bogusa_website/archive/refs/tags/v1.0.3.zip' -OutFile $zip

# 3) распаковать в свою папку (внутри появится Bogusa_website-1.0.3)
$dst = "$env:USERPROFILE\Bogusa_website"
New-Item -ItemType Directory -Force -Path $dst | Out-Null
Expand-Archive -Path $zip -DestinationPath $dst -Force

# 4) установить и запустить
cd "$dst\Bogusa_website-1.0.3"
.\start.ps1
```

**Если Node.js не установлен** — скрипт предложит поставить его сам (через `winget`). Можно
поставить и загодя, одной командой:

```powershell
winget install --exact --id OpenJS.NodeJS.LTS
```

После установки **закройте и снова откройте PowerShell** (чтобы команда `node` попала в PATH),
затем повторите шаги 2–4. Проверка: `node -v` должно показать v22.x, v24.x или v26.x.

Скрипт также принимает `-InstallNode`, чтобы поставить Node.js через winget без вопросов:

```powershell
.\start.ps1 -InstallNode
```

Скачать можно и вручную: страница [Releases](https://github.com/Igorr112323/Bogusa_website/releases) →
у версии **v1.0.3** ссылка **Source code (zip)**.

Скрипт `start.ps1` сам: проверит Node.js, выполнит `npm install`, создаст `.env`,
инициализирует базу с администратором и демо-данными и запустит сервер.
**Пароль администратора** он напечатает в этом же окне — сохраните его.

Если PowerShell запрещает запуск скриптов (ошибка про Execution Policy), используйте:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Или просто дважды щёлкните по файлу **`start.cmd`** в папке проекта.

Полезные варианты запуска:

```powershell
.\start.ps1 -Port 8080 -StaffPort 8081   # другие порты (студенты и панели)
.\start.ps1 -NoDemo         # без демонстрационных дисциплин и ответов
.\start.ps1 -Reset          # пересоздать базу (удалит текущие анкеты!)
.\start.ps1 -SkipInstall    # не запускать npm install
```

### Как открыть сайт

После запуска откройте в браузере:

| Роль | Адрес | Доступ |
| --- | --- | --- |
| Студенты | http://localhost:3000/ | без входа, можно раздать QR/ссылку |
| Студенты (анкета) | http://localhost:3000/form.html | без входа |
| Преподаватель | http://localhost:3001/portal/ | `ivanova` / `Teacher#2026pass` (демо) |

### Обновление до новой версии

Вся база (анкеты, аккаунты, дисциплины) лежит в папке `data`, настройки — в `.env`.
При обновлении перенесите их в новую версию:

```powershell
# 1) скачать архив новой версии и распаковать в отдельную папку
$ProgressPreference = 'SilentlyContinue'
Invoke-WebRequest 'https://github.com/Igorr112323/Bogusa_website/archive/refs/tags/v1.0.3.zip' -OutFile "$env:TEMP\update.zip"
Expand-Archive "$env:TEMP\update.zip" -DestinationPath "$env:USERPROFILE\Bogusa_new" -Force
$old = "$env:USERPROFILE\Bogusa_website\Bogusa_website-1.0.2"     # папка текущей версии (укажите свою)
$new = Get-ChildItem "$env:USERPROFILE\Bogusa_new" -Directory | Select-Object -First 1   # новая версия

# 2) перенести свою базу и настройки
Copy-Item "$old\data" "$($new.FullName)\data" -Recurse -Force
Copy-Item "$old\.env" "$($new.FullName)\.env" -Force

# 3) запустить новую версию (при необходимости зависимости доустановятся сами)
cd $new.FullName
.\start.ps1
```

Список всех выпущенных версий — на [странице релизов](https://github.com/Igorr112323/Bogusa_website/releases).
Перед обновлением стоит скопировать папку `data` в надёжное место — там вся база анкет.

### Если что-то пошло не так (Windows)

| Симптом | Что делать |
| --- | --- |
| `npm : Имя "npm" не распознано`, «Node.js не найден» | Поставьте Node.js: `winget install --exact --id OpenJS.NodeJS.LTS`, затем закройте и заново откройте PowerShell. Либо запустите `.\start.ps1 -InstallNode` — скрипт установит Node.js сам |
| «выполнение сценариев отключено» | Запустите `powershell -ExecutionPolicy Bypass -File .\start.ps1` или используйте `start.cmd` |
| Долго скачивается архив | Добавьте `$ProgressPreference = 'SilentlyContinue'` (см. блок выше) или скачайте zip вручную со страницы релизов |
| При `npm install` появилось предупреждение `install scripts ... not yet covered by allowScripts` | Так ведут себя npm 11.19+ и 12: без явного разрешения install-скрипты нативных пакетов не выполняются. В проекте уже есть поле `allowScripts`, поэтому достаточно удалить `node_modules` и выполнить `npm install` заново |
| `npm start` сразу падает с `Assertion failed: (env) != nullptr` (в тексте видно `node::RemoveEnvironmentCleanupHook`) | Сервер не смог загрузить нативный драйвер и упал на встроенном SQLite этой сборки Node.js. Лечение: `npm run dbcheck`, затем `npm install better-sqlite3@^12`, снова `npm start`. Проверьте также, что Node.js 22 или новее (`node -v`) |
| `npm install` не может собрать `bcrypt`/`better-sqlite3` | Это опциональные пакеты: сервис работает и без них (пароли — scrypt, база — встроенный SQLite в Node 22+). Но для стабильности лучше поставить готовый бинарник: `npm install better-sqlite3@^12`. Диагностика: `npm run doctor` |
| Порт занят (`EADDRINUSE`) | Запустите на других портах: `.\start.ps1 -Port 8080 -StaffPort 8081` либо закройте прошлое окно сервера |
| «Отказано в доступе» при записи в `data` | Распакуйте проект в свою папку пользователя (например, `%USERPROFILE%\Bogusa_website`) или задайте `DATA_DIR` в `.env` |
| Нужно сбросить всё и начать заново | `.\start.ps1 -Reset` (или удалите папку `data` и запустите снова) |

> Брандмауэр Windows может спросить разрешение для `node.exe` при первом запуске —
> достаточно разрешить доступ в частных сетях (сервер слушает порт на вашем компьютере).

## Роли и сценарии работы

### Студент (без регистрации и авторизации)

1. Открывает общую ссылку или сканирует QR-код (адрес — студенческий порт, по умолчанию 3000).
2. На главной видит дисциплины карточками: у каждой две крупные плитки-«двери» — янтарная
   «Оценить занятие» и белая «Оценить дисциплину». Выпадающих списков и ручного ввода на
   главной нет (если у дисциплины не добавлены темы, янтарная плитка неактивна).
3. В анкете сверху выбирает дисциплину и тему занятия из списков, а вид анкеты ниже
   переключает двумя крупными кнопками (для итоговой анкеты поле темы скрыто).
4. Отмечает оценки по шкале 1–5 (все пункты обязательны), при желании пишет ответы на
   открытые вопросы.
5. Нажимает «Отправить» и видит подтверждение.

На студенческих страницах нет ни ссылок, ни упоминаний входа, портала и админ-панели.

Студенческие страницы не используют cookies для идентификации, ничего не пишут в
`localStorage`/`sessionStorage` и не запрашивают ФИО, группу или e-mail.

### Преподаватель

- Входит по логину и паролю, выданным администратором.
- Видит **только свои** дисциплины и темы: чужие запросы отклоняются (403).
- Разделов три: «Отчёт», «Мои темы» и «Пароль». На широком экране — боковое меню, на узком та
  же полоса над содержимым. Отдельных разделов «Обзор» и «Отзывы студентов» нет: всё нужное
  собрано в отчёте, графики не выводятся.
- «Отчёт»: сверху выбор дисциплины, ниже две крупные кнопки вида анкеты («Анкета по занятию» и
  «Итоговая анкета по дисциплине»), для занятия появляется список тем, затем период — две даты
  и быстрые кнопки «Неделя», «Месяц», «Семестр», «Всё время».
- Под фильтрами — «Всего анкет» и «Средний балл» (обе цифры считаются по выбранному периоду:
  либо за всё время, либо с указанной даты), затем средние баллы по каждому пункту,
  распределение оценок (сколько раз поставили 1…5), доля ответов «4 и 5» и разбивка по занятиям.
- Комментарии студентов идут сразу под оценками: один ответ — одна строка, текст крупно, а дата
  ответа, дата занятия, тема и тип анкеты — отдельными метками. Рядом поиск и переключатель
  «только новые».
- Новые ответы: сервер хранит момент последнего захода в «Отчёт» (таблица `teacher_views`, только
  user_id и timestamp — данные студентов по-прежнему обезличены). Всё пришедшее после этого
  момента помечено «новое», а на разделе «Отчёт» в меню виден счётчик; при открытии отчёта он
  сбрасывается запросом `POST /api/teacher/seen`.
- «Мои темы»: преподаватель создаёт дисциплины (они сразу закрепляются за ним), добавляет темы
  занятий по одной и списком (одна тема в строке, дата через `|`), правит названия и даты,
  выключает дисциплины и темы, берёт отсюда ссылку для группы. Назначать дисциплину другому
  преподавателю и удалять их может только администратор.
- Кнопка «Скачать CSV» — выгрузка ответов для Excel (разделитель `;`, кодировка UTF-8 с BOM).
- «Печать / PDF» — отчёт можно сохранить в PDF средствами браузера.

### Администратор

- Создаёт аккаунты преподавателей (логин + пароль), сбрасывает пароли, блокирует доступ.
- Управляет дисциплинами: название, код, преподаватель, статус «открыта/выключена».
- Управляет темами занятий: по одной или списком (массовое добавление строк).
- Видит сквозные отчёты по всем преподавателям и дисциплинам, выгружает CSV.
- Получает QR-код и ссылку на анкету для конкретной дисциплины.
- Просматривает журнал действий (кто создал дисциплину, кто сбросил пароль и т. д.).

## Как выдать доступ преподавателю

1. Войдите как администратор: `/login` → логин `admin` и пароль из консоли/`.env`.
2. Раздел **«Преподаватели»** → кнопка **«+ Новый преподаватель»**.
3. Укажите **логин** (латиница, цифры, `.` `_` `-`, 3–32 символа) и **ФИО**. Поле пароля можно
   оставить пустым — сервер сгенерирует надёжный пароль вида `4EZsu-D6973-DRTCd-3FdZ6`.
4. Пароль показывается **один раз** — скопируйте и передайте преподавателю лично или по
   защищённому каналу.
5. При первом входе преподаватель обязан сменить временный пароль — до этого отчёты недоступны.

Дополнительно:

- **«Новый пароль»** — сброс забытого пароля (все активные сессии преподавателя завершаются).
- **«Заблокировать»** — мгновенно закрывает доступ, не удаляя дисциплины и отзывы.
- **«Удалить»** — дисциплины и отзывы можно передать другому преподавателю или оставить без него.

## Как раздать анкету студентам (ссылка и QR)

**Вариант 1. Общая ссылка.** `/form.html` — студент сам выбирает дисциплину, тему и тип анкеты.

**Вариант 2. QR-код на конкретную дисциплину.** Админка → «Дисциплины и темы» → **«Ссылка/QR»**,
либо раздел **«QR и ссылки»**. QR можно скачать в PNG и распечатать/показать на экране.

**Вариант 3. Прямая ссылка из QR/чата.** Формат параметров:

```
/form.html?discipline=3&form=lesson&topic=12   # сразу к вопросам по занятию №12
/form.html?discipline=3&form=final             # сразу к итоговой анкете
```

**Вариант 4. Встраивание в LMS.** Анкету можно вложить в iframe:

```html
<iframe src="https://feedback.example.ru/form.html?discipline=3" width="100%" height="900"
        style="border:0" title="Анкета"></iframe>
```

По умолчанию встраивание разрешено с любого источника (`FRAME_ANCESTORS=*`). Чтобы ограничить,
укажите домены: `FRAME_ANCESTORS='self' https://lms.university.ru`.

> Если сайт работает по HTTPS, ссылка в QR-коде должна начинаться с `https://` — задайте
> `PUBLIC_BASE_URL=https://feedback.example.ru` в `.env`, иначе в QR попадёт адрес локальной машины.

## API

Публичные (без авторизации) — доступны на **студенческом** порту (`PORT`, по умолчанию 3000)
и на служебном:

| Метод | Адрес | Описание |
| --- | --- | --- |
| `GET` | `/api/meta` | Список анкет и настройки публичной части |
| `GET` | `/api/forms/:type` | Структура анкеты (`lesson` или `final`) |

| `GET` | `/api/disciplines/:id` | Дисциплина с темами |
| `POST` | `/api/responses` | Отправка анкеты (rate-limit, honeypot, валидация) |
| `GET` | `/api/privacy` | Что сервис собирает и что не собирает |

Пример отправки анкеты:

```bash
curl -X POST http://localhost:3000/api/responses \
  -H 'Content-Type: application/json' \
  -d '{
        "discipline_id": 1,
        "topic_id": 2,
        "form_type": "lesson",
        "started_at": 1730000000000,
        "scores": {
          "l_goals":5,"l_logic":4,"l_relevance":5,"l_visual":5,"l_examples":4,
          "l_clarity":5,"l_attention":4,"l_interaction":5,"l_atmosphere":5,"l_pace":4,
          "l_org":5,"l_readiness":4
        },
        "comments": {"l_liked":"Понятные примеры","l_improve":"Больше практики"}
      }'
# → {"ok":true,"id":42,"message":"Спасибо! Ваш ответ сохранён анонимно."}
```

Полный список ключей пунктов — в `server/questions.js` (или `GET /api/forms/lesson`,
`GET /api/forms/final`). Ключей снятых с анкеты вопросов (`l_wishes`, `f_useful`, `f_difficult`,
`f_wishes`) сервер больше не принимает, но ранее собранные ответы по ним остаются в базе и
попадают в отчёты и выгрузку CSV отдельной группой.

Аутентификация и панели — **только служебный порт** (`STAFF_PORT`, по умолчанию 3001).

## Безопасность

Свой развёрнутый сервер можно проверить тем же способом, которым пользуются аудиторы, - но без
сторонних утилит и без обращения к чужим адресам:

```bash
npm run secaudit                      # проверка localhost:3000 и localhost:3001
npm run secaudit -- --verbose         # показать и пройденные проверки
npm run secaudit -- --student http://127.0.0.1:3000 --staff http://127.0.0.1:3001 --json audit.json
```

Скрипт (`scripts/security-audit.js`) смотрит заголовки (CSP, `frame-ancestors`, nosniff, кэш),
служебные пути (`.env`, `.git`, файл базы, `node_modules`), список каталогов, лишние HTTP-методы,
CORS, подстановку `Host`, открытые редиректы, утечки в текстах ошибок, флаги куки и то, что реально
отдаётся браузеру (никаких описаний серверных механизмов и `innerHTML`). В конце - оценка 0-100 и
список находок; код выхода 1, если есть критичные или высокие. `--skip-throttle` пропускает
проверку перебора паролей, чтобы не закрывать себе вход на 10 секунд. Инструменты вроде
`secureprobe` и OWASP-сканеров ставить не нужно: они рассчитаны на публичный https-сайт и на PHP,
а наш стек - Node.js без внешних зависимостей и без CDN. и приватность

Что реализовано:

- **Пароли** — bcrypt (cost 12). Если нативный модуль `bcrypt` недоступен в вашем окружении,
  автоматически используется встроенный `scrypt` (N=16384) с тем же интерфейсом — открытые
  пароли не хранятся никогда. Пароли не попадают в логи и журнал аудита.
- **JWT с ограниченным сроком** (по умолчанию 8 часов). Токен передаётся в httpOnly-cookie
  (`SameSite=Lax`, `Secure` при включённом `COOKIE_SECURE`). Смена или сброс пароля увеличивает
  `token_version`, поэтому старые токены мгновенно становятся недействительными.
- **Разграничение доступа по ролям**: middleware `requireAuth` / `requireRole`; преподаватель
  получает только свои дисциплины, попытка обратиться к чужим отдаёт 403 (проверяется
  автотестами). Админские маршруты закрыты ролью `admin`.
- **Проверка заголовка Host**: адреса для ссылок и QR-кодов берутся либо из `PUBLIC_URL`, либо из
  имени хоста запроса - и только если это localhost, частный адрес (`10.x`, `192.168.x`,
  `172.16-31.x`) или домен из `ALLOWED_HOSTS`. Иначе подставной `Host` не сможет превратиться
  в ссылку, которую преподаватель покажет студентам.
- **Защита от перебора пароля**: после `LOGIN_MAX_ATTEMPTS` (по умолчанию 5) неверных попыток вход
  недоступен `LOGIN_COOLDOWN_SECONDS` (по умолчанию 10) секунд. Пауза фиксированная: она не
  увеличивается при повторных ошибках и одинакова для преподавателя и администратора. Успешный вход
  обнуляет счётчик. Сверху стоят и общие лимиты на отправку анкет и на API.
- **Rate-limit**: лимиты на отправку анкет (защита от накрутки) и общий лимит на API.
  IP-адрес используется только в памяти счётчика и **не сохраняется в базу**.
- **Валидация**: типы, диапазоны (оценки строго 1–5), длины (комментарии ≤ 2000 символов),
  список допустимых ключей вопросов, проверка принадлежности темы дисциплине, суммы текста
  за запрос. Ошибки возвращаются понятными сообщениями без внутренних деталей.
- **Защита от XSS**: строгая CSP без `unsafe-inline`, весь вывод на фронтенде через
  `textContent` (в проекте нет ни одного `innerHTML`), пользовательский текст дополнительно
  HTML-экранируется на сервере перед сохранением.
- **Прочее**: helmet (`nosniff`, `no-referrer`, `Permissions-Policy`), лимит размера JSON
  (128 КБ), запрет индексации (`X-Robots-Tag: noindex`), журнал действий администратора,
  анти-бот «ловушка» (скрытое поле) и минимальное время заполнения анкеты.
- **Анонимность студентов**:
  - в схеме БД нет ни одной колонки с ФИО, группой, e-mail, IP или cookie-идентификатором —
    таблица `responses` хранит только дисциплину, тему, тип анкеты, время и оценки;
  - открытые ответы лежат в отдельной таблице и связаны только с анкетой, а не со студентом;
  - IP адрес не логируется приложением и не пишется в базу (только счётчики rate-limit в памяти);
  - `MIN_ANSWERS_TO_SHOW` позволяет скрывать отчёты, пока ответов слишком мало (защита от
    «вычисления» автора по единственному отзыву);
  - автотесты проверяют отсутствие «запрещённых» колонок в схеме БД.
- Дополнительно не хранится ничего, что могло бы связать повторные ответы одного студента:
  между анкетами нет идентификатора.

Что стоит сделать перед боевым запуском:

1. Задать `JWT_SECRET` (≥ 32 символов) и сменить пароль администратора.
2. Включить HTTPS и `COOKIE_SECURE=true`.
3. Ограничить `FRAME_ANCESTORS` вашими доменами, если встраивание не нужно.
4. Настроить резервное копирование файла `data/feedback.sqlite` (например, `sqlite3 ... ".backup"`).

## Развёртывание на сервере

### Вариант 1: systemd + nginx

```bash
git clone <репозиторий> /opt/bogusa-feedback
cd /opt/bogusa-feedback
npm install --omit=dev
cp .env.example .env && nano .env      # задайте JWT_SECRET, ADMIN_PASSWORD, STAFF_PORT, PUBLIC_BASE_URL, COOKIE_SECURE=true
npm run seed                            # создаст администратора и структуру
sudo npm install -g pm2 && pm2 start server/index.js --name feedback && pm2 save
```

Один процесс поднимает два порта: `PORT` (студенты) и `STAFF_PORT` (вход и панели).
Служебный порт во внешний доступ не выпускайте — достаточно проксировать только студенческий.

`/etc/nginx/sites-available/feedback` — студенческий сайт (публичный домен):

```nginx
server {
    listen 443 ssl http2;
    server_name feedback.university.ru;

    ssl_certificate     /etc/letsencrypt/live/feedback.university.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/feedback.university.ru/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Панели (порт 3001) — отдельным доменом или только во внутренней сети:

```nginx
server {
    listen 443 ssl http2;
    server_name feedback-admin.university.ru;

    ssl_certificate     /etc/letsencrypt/live/feedback-admin.university.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/feedback-admin.university.ru/privkey.pem;

    # при желании ограничьте доступ подсетью кафедры
    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

В `.env` при этом задайте `PUBLIC_BASE_URL=https://feedback.university.ru` — ссылки и QR-коды
для студентов будут строиться от публичного студенческого адреса.


Порт панелей в примере проброшен только на `127.0.0.1` — наружу студенческий сайт виден,

База и секрет живут в томе `/data`, поэтому данные сохраняются между перезапусками.

## Как поменять формулировки вопросов

Все вопросы собраны в `server/questions.js`, эталон формулировок — PDF-анкеты в `docs/`.
Текст пунктов можно править свободно, на уже собранные данные это не влияет.
**Ключи (`key`) менять нельзя**: по ним хранятся оценки (`l_goals`, `f_feedback` и т. д.),
иначе старые ответы «потеряются» в отчётах.

```js
{
  key: 'l_pace',          // ключ: не менять после запуска
  kind: 'scale',          // scale — оценка 1–5, text — открытый ответ
  label: 'Темп подачи: Темп занятия был оптимальным (не слишком быстрый и не слишком затянутый).',
}
```

Пункт показывается студенту ровно так: над вопросом только его текст, под ним шкала 1–5.
Пояснений, подсказок и примеров у пунктов нет — они намеренно убраны из формы.

- **Новый пункт**: допишите объект в нужный блок. Старые анкеты просто не будут иметь оценки
  по новому ключу — в отчёте по нему будет «—» и `ответов: 0`.
- **Пункт убран из анкеты**: удалите его из `sections` и добавьте в `LEGACY_QUESTIONS` —
  собранные ранее ответы останутся в базе, попадут в отчёты отдельной группой
  «вопрос снят с анкеты» и в CSV отдельными колонками.
- **Совпал смысл** — оставляйте прежний ключ, чтобы история оценок не разрывалась.

После правки запустите `npm test`: `tests/questions.test.js` сверяет названия, блоки и дословные
формулировки пунктов с PDF.

## Частые вопросы и решения проблем

**В консоли предупреждение `ExperimentalWarning: SQLite is an experimental feature`.**
Это Node.js сообщает о встроенном модуле `node:sqlite` — значит, используется запасной драйвер.
Приложение работает, но лучше переключиться на нативный: `npm install better-sqlite3@^12`
(готовый бинарник, компилятор не нужен). Переключение автоматическое, проверить можно
командой `npm run dbcheck`.

**`npm install` пишет `install scripts ... not yet covered by allowScripts` и не собирает
`bcrypt`/`better-sqlite3`.**
Начиная с npm 11.19 (в npm 12 — жёстко) скрипты установки зависимостей не выполняются, пока они
не перечислены в поле `allowScripts` файла `package.json`. В проекте оно есть:

```json
"allowScripts": { "bcrypt": true, "better-sqlite3": true }
```

Если папка `node_modules` осталась с прошлого запуска, выполните заново:

```powershell
Remove-Item -Recurse -Force node_modules
npm install
npm run dbcheck
```

Принудительно разрешить установку конкретного пакета можно и командой
`npm pkg set allowScripts.better-sqlite3=true`.

**`npm start` падает с `Assertion failed: (env) != nullptr`.**
Этот сбой возникает, когда сервер уходит на встроенный `node:sqlite`, а он в вашей сборке Node.js
неисправен (известная беда Node.js 24.20 на Windows при повреждённом драйвере). Симптом: консоль
печатает стек с `node::RemoveEnvironmentCleanupHook` вместо строки «Сервер запущен».
Порядок действий:

```powershell
node -v                              # нужна версия 22 или новее
npm run dbcheck                      # покажет, какой драйвер базы данных выбран
npm install better-sqlite3@^12       # готовый бинарник под Node 22/24/25/26
npm run dbcheck                      # должно быть [ok] ... better-sqlite3
npm start
```

Если при установке видно, что готовый бинарник не скачивается (ошибки сети, прокси или
сертификата — файл берётся с GitHub), повторите установку из другой сети: для нативного
драйвера больше ничего не требуется.

В версии **v1.0.2** и новее этот сценарий закрыт: `better-sqlite3` объявлен версии `^12.11.1`
(есть готовый бинарник для Node 24), а install-скрипты разрешены полем `allowScripts`.
Скрипт `start.ps1` проверяет драйвер до старта сервера — вместо нативного падения вы увидите
понятное сообщение с командами.

**Как понять, какой драйвер базы данных используется?**
`npm run dbcheck` — печатает выбранный драйвер, версию и причину выбора. Принудительно выбрать
можно переменной окружения: `DB_DRIVER=better-sqlite3` (или `DB_DRIVER=node:sqlite`) в `.env`.

**Преподаватель не видит свою дисциплину.**
Проверьте в админке: у дисциплины должен быть указан преподаватель, а у дисциплины — хотя бы одна
активная тема (иначе она не видна студентам) и статус «открыта».

**Студенты не находят дисциплину на странице анкеты.**
Студентам показываются только дисциплины со статусом «открыта» **и** хотя бы одной активной темой.

**QR-код ведёт на `localhost`.**
Задайте `PUBLIC_BASE_URL=https://ваш-домен` в `.env` и перезапустите сервер: в QR попадёт этот адрес.
Ссылки и QR-коды всегда строятся на студенческий порт (`PORT`), даже когда вы открываете их
в админ-панели на порту `STAFF_PORT` — адрес панелей студентам не показывается.

**Студент открывает ссылку и видит «Страница не найдена».**
Проверьте порт: анкета живёт на `PORT` (по умолчанию 3000), а `/login`, `/portal/` и `/admin/` —
на `STAFF_PORT` (по умолчанию 3001). На студенческом порту служебные разделы отдают 404 — так
и задумано.

**Просит подождать после входа.**
После 5 неверных паролей подряд вход приостанавливается на 10 секунд (оба значения настраиваются:
`LOGIN_MAX_ATTEMPTS` и `LOGIN_COOLDOWN_SECONDS` в `.env`). Пауза всегда одинаковая, она не растёт,
а администратор может сбросить её, просто подождав. Отключить паузу: `LOGIN_MAX_ATTEMPTS=0`.

**Не приходят анкеты, ответ `429`.**
Сработал лимит: по умолчанию 15 отправок с одного IP за час. Измените `RATE_LIMIT_SUBMIT` и
`RATE_LIMIT_SUBMIT_WINDOW_MIN` в `.env`. Если перед сервером несколько прокси, поправьте
`TRUST_PROXY_HOPS`, иначе все студенты будут выглядеть «одним IP».

**Нужно скрывать отчёты, пока ответов мало.**
Установите `MIN_ANSWERS_TO_SHOW=3` (или больше) — преподаватель увидит плашку о том, что
результаты скрыты для защиты анонимности.

**Как полностью сбросить данные?**
`npm run reset` (удалит файл БД и создаст структуру заново) или удалите каталог `data/` вручную.

**Как забрать данные для отчёта кафедры?**
Админка → «Отчёты» → «Скачать CSV», либо `GET /api/admin/export.csv?from=2026-09-01&to=2026-12-31`.
Файл открывается в Excel с корректной кириллицей.
